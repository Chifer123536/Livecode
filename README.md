# livecode-drills — тренажёр лайвкода

Задачи с автотестами, прогресс по результатам тестов и карточки для разбора в бесплатном Клоде.
Всё работает из VS Code, без браузера.

---

## Быстрый старт

```bash
yarn t
```

Это watch-режим тестов. Открываешь `src/drills/01-basics/tasks.ts`, стираешь `todo()`,
пишешь тело функции — тесты пересчитываются на каждое сохранение.

Рекомендуемая раскладка: слева файл с задачами, снизу терминал с `yarn t`.
Красное → зелёное, и дальше.

---

## Команды

| Команда | Что делает |
|---|---|
| `yarn t` | тесты в watch-режиме — основной рабочий цикл |
| `yarn test` | однократный прогон всех тестов |
| `yarn task` | список паков задач |
| `yarn task ARR` | список задач пака |
| `yarn task ARR-14` | карточка задачи: условие + заготовка + тесты |
| `yarn task ARR-14 -c` | то же, но сразу в буфер обмена |
| `yarn task ARR-14 -s` | карточка вместе с эталонным решением |
| `yarn task next` | первая нерешённая задача |
| `yarn progress` | где ты сейчас, попаковый прогресс + `PROGRESS.md` |
| `yarn verify` | самопроверка тренажёра: тесты и типы против эталонов |
| `yarn types` | проверка типов; красное в нерешённых задачах — это норма |
| `yarn dev` | браузерная песочница для React-задач |

## Разбор задачи в бесплатном Клоде

```bash
yarn task ASY-07 -c
```

Карточка уже в буфере. Открываешь claude.ai, вставляешь, отправляешь.
Внутри карточки лежит готовый промпт: Клод обязан сначала переформулировать условие,
дать уточняющие вопросы к интервьюеру и алгоритм словами — и только потом код.
Файлы прикладывать не нужно, карточка самодостаточная.

## Как устроен пак

```
src/drills/02-arrays/
├─ pack.json        код пака, уровень, норматив
├─ tasks.ts         ← ЗДЕСЬ ПИШЕШЬ ТЫ
├─ tasks.test.ts    тесты, они же формальное условие
└─ solution.ts      эталон + разбор, открывать после попытки
```

Каждая задача обёрнута в `// #region BAS-07 | Заголовок | ★☆☆` … `// #endregion`.
В VS Code это сворачивается: `Ctrl+K Ctrl+0` свернёт весь файл в список задач,
`Ctrl+K Ctrl+J` развернёт обратно. Удобно идти сверху вниз и не видеть лишнего.

Звёзды — сложность: ★☆☆ разогрев, ★★☆ типовая задача с собеса, ★★★ на подумать.

## Правила, без которых тренажёр не работает

1. **Сначала вслух.** Одним предложением: что делает функция и как. Не смог сказать —
   решения ещё нет, код писать рано.
2. **Не подглядывать в `solution.ts`,** пока не потратил на задачу норматив.
3. Посмотрел разбор — **сотри свой код и напиши заново сам.** Копирование не считается.
4. Задача сдана, когда написана **с нуля, без разбора, в норматив.** Первый проход не считается,
   считается повтор на следующий день.
5. `yarn progress` не врёт: там не галочки, а реальные результаты тестов.

## Протокол лайвкода на собесе

Порядок, от которого не отступать:

1. **Уточни условие.** Два-три вопроса: размер данных, можно ли мутировать вход,
   что делать с пустым и невалидным. Плюс в карму ставят ещё до первой строки кода.
2. **Проговори пример.** «На вход `[1,2,3]`, жду `[2,4,6]`. Верно?»
3. **Алгоритм словами.** До кода.
4. **Пиши тупое рабочее решение.** Красоту и оптимизацию — потом и вслух.
5. **Проверь края:** пустой массив, один элемент, отрицательные, дубликаты, `null`.
6. **Назови сложность:** «один проход, O(n) по времени, O(n) по памяти из-за Set».

Что убивает собес: молчание, попытка сразу писать идеально, «я не знаю» без продолжения.
Рабочая формулировка: «Точно не помню синтаксис, но идея такая: … Сейчас напишу как помню,
потом поправлю.»

## Два особых пака

**`TS` — TypeScript.** Задачи 13-26 это чистые типы, их проверяет не рантайм, а компилятор.
Строки `type _TS13 = Expect<Equal<...>>` — это и есть тесты, удалять их нельзя.
Пока тип написан неверно, строка подсвечена красным прямо в редакторе,
а `yarn progress` покажет у задачи пометку `[типы: N]`.

**`QZ` — что выведет.** Здесь ничего не реализуют, здесь предсказывают.
Тесты этого пака выполняют тот же код и сравнивают твой ответ
с реальным поведением движка — спорить не с кем.
