# Livecode — тренажёр лайвкода

548 задач с автотестами: JS, TypeScript, React, алгоритмы, браузер. Прогресс считается по
результатам тестов, а не по галочкам. Работает из редактора, браузер не нужен.

---

## Старт

```bash
yarn install
yarn menu
```

`yarn menu` открывает меню тренажёра на весь терминал:

| Клавиша | Что делает |
|---|---|
| `↑` `↓` | выбор пункта, в документах — прокрутка |
| `Enter` | открыть |
| `◂` `▸` | соседняя задача: на главном экране, в задаче, условии, разборе. В списке пака — соседний пак |
| `/` | поиск по списку |
| `↓` с последнего пункта, `Tab` | в консоль под меню |
| `Esc` | назад. С первого экрана никуда не уводит |
| `q` | выход. Ещё — `Ctrl+C` на первом экране или пункт «Выход» |

«Решать» открывает задачу в VS Code, меню остаётся на месте. Условие, проверка и разбор решения
открываются экранами прямо в меню.

### Консоль в меню

Под меню — рабочая консоль на том же экране. Меню и консоль видны одновременно, фокус
переключается стрелками: `↓` с последнего пункта меню — в консоль, `↑` в консоли — обратно.

| В консоли | Что делает |
|---|---|
| `ok BAS-08`, `yarn ok BAS-08` | команды тренажёра — с `yarn` и без, запускаются напрямую и быстро |
| `git status`, `ls`, … | любые команды PowerShell |
| `Enter` / `Tab` | выполнить / дополнить команду или код задачи |
| `Ctrl+↑` `Ctrl+↓` | история команд |
| `PgUp` `PgDn` | листать вывод |
| `Ctrl+C` | остановить команду (или очистить строку) |
| `↑`, `Esc` на пустой строке | обратно в меню |

Пункты меню, которым нужен вывод команды — «Прогресс», сброс, инструменты, watch, — выполняются
в этой же консоли. Меню никогда не уходит с экрана.

Из терминала то же самое:

```bash
yarn go      # открыть следующую нерешённую задачу
yarn ok      # проверить её, когда написал
yarn how     # разбор решения по шагам
```

`yarn go` показывает условие, приёмку и открывает файл в редакторе. **Тесты при этом не
запускаются** — пока пишешь, консоль молчит. `yarn ok` гоняет проверки только этой задачи
(секунда) и печатает, что прошло, что упало и на какой строке.

Конкретная задача — `yarn go ARR-14`, проверить конкретную — `yarn ok ARR-14`,
проверить весь пак — `yarn ok ARR`.

## Разбор решения

`yarn how` (или пункт «Разбор решения» в меню) показывает эталон и разбирает его:

- **идея** — в одну-две фразы, что делает решение;
- **из чего состоит** — каждая конструкция отдельно: что делает и зачем;
- **по шагам** — реальный вызов, прогнанный вручную: какое действие, какое состояние после него;
- **крайние случаи** — пустой ввод, ноль, отрицательные, и почему решение их выдерживает.

Итог каждого примера сверяется с настоящим запуском эталона в `yarn verify` — разбор не может
показать ответ, которого код на самом деле не даёт. Разборы лежат рядом с задачами,
в `src/drills/<пак>/walkthrough.md`.

Открывай после своей попытки: разбор показывает готовое решение.

## Терминал: шпаргалка и Tab

Подключается само — при `yarn install` и при первом запуске меню: в профиль PowerShell
(`$PROFILE`) дописывается блок из трёх строк между метками `livecode trainer`. Срабатывает в новом
окне терминала. Выключатель — `yarn menu` → «Внешний вид» → PowerShell, или командами
`yarn shell` / `yarn shell --off`. Выключенное руками обратно само не включается.

Что даёт:

- при входе в папку тренажёра печатается шпаргалка: прогресс, текущая задача, четыре главные команды;
- `Tab` дополняет `yarn`: после `yarn ` — команды тренажёра, после `yarn go ` / `ok` / `how` /
  `task` / `clean` / `watch` — коды задач и паков. `Ctrl+Пробел` показывает список с пояснениями.

Вне папки тренажёра `yarn` дополняется как обычно.

## Как это устроено

Один пак — одна тема, одна задача — один файл:

```
src/drills/02-arrays/
├─ pack.json        код пака, уровень, норматив по времени
├─ tasks/
│  ├─ ARR-01.ts     ← ЗДЕСЬ ПИШЕШЬ ТЫ: одна задача, одна функция
│  ├─ ARR-02.ts
│  └─ …
├─ tasks.ts         бочка с реэкспортами, руками не трогать
├─ tasks.test.ts    тесты, они же формальное условие задачи
└─ solution.ts      эталон + разбор, открывать после своей попытки
```

Звёзды — сложность: ★☆☆ разогрев, ★★☆ типовая задача с собеса, ★★★ на подумать.

Четыре вещи, которые надо знать про механику:

1. **Тесты — это условие.** Не понял формулировку в комментарии — читай тесты, там ответ.
2. **Прогресс не врёт.** Сданным считается только то, что реально зелёное после прогона.
   Ручных галочек в системе нет.
3. **Задача сдана, когда зелены тесты И типы.** `yarn ok` проверяет и то, и другое.
   В паках `TS` и `TSB` часть задач проверяет только компилятор — про них ниже.
4. **`yarn verify` проверяет сам тренажёр:** гоняет тесты и разборы против эталонов и типы решений.
   Если он красный — сломан тренажёр, а не ты.

## Команды

Рабочий цикл — четыре команды:

| Команда | Что делает |
|---|---|
| `yarn menu` | меню: то же самое стрелками |
| `yarn go` | открыть следующую нерешённую задачу, **без тестов** |
| `yarn ok` | проверить текущую задачу — секунда |
| `yarn how` | разбор решения текущей задачи по шагам |

Всё остальное по необходимости:

| Команда | Что делает |
|---|---|
| `yarn go ARR-14` | открыть конкретную задачу |
| `yarn go ARR` | открыть первую нерешённую в паке |
| `yarn go ARR-14 -n` | не открывать редактор, только карточка |
| `yarn ok ARR-14` | проверить конкретную задачу |
| `yarn ok ARR` | проверить весь пак |
| `yarn ok --all` | проверить весь тренажёр (~10 секунд) |
| `yarn how ARR-14` | разбор конкретной задачи |
| `yarn watch` | держать тесты текущей задачи запущенными |
| `yarn task` | список паков |
| `yarn task ARR` | список задач пака |
| `yarn task ARR-14` | карточка задачи: условие + заготовка + тесты |
| `yarn task ARR-14 -c` | то же, но сразу в буфер обмена |
| `yarn task ARR-14 -s` | карточка вместе с эталонным решением |
| `yarn progress` | полный прогон + таблица + перезапись `PROGRESS.md` |
| `yarn progress ARR` | то же, но с разбивкой по задачам пака |
| `yarn clean ARR-14` | сбросить задачу к заготовке |
| `yarn test` / `yarn t` | сырой vitest: разовый прогон и watch |
| `yarn typecheck` | проверка типов всего проекта |
| `yarn verify` | самопроверка тренажёра: тесты, разборы и типы против эталонов |
| `yarn dev` | браузерная песочница для React-задач |

Меню разворачивается на весь терминал и пересчитывается при изменении размера окна.
Цвета настраиваются: `yarn menu` → **Внешний вид**. Шесть тем, три уровня контраста, стиль полосы
прогресса и заливка фона (нужна, если терминал прозрачный). Значение меняется стрелками `◂ ▸`,
экран перерисовывается сразу. Выбор лежит в `.ui.json` и действует на все команды, не только на меню.

Прогресс ведёт сама `yarn ok`: после проверки задача помечается в `.progress.json`, и «следующая
нерешённая» сразу знает правду. `yarn progress` нужен только для контрольной сверки — он гоняет
всё подряд и потому долгий.

## Разбор задачи в бесплатном Клоде

```bash
yarn task ASY-07 -c
```

Карточка уже в буфере — вставляешь в claude.ai и отправляешь. Внутри готовый промпт:
Клод обязан сначала переформулировать условие, задать уточняющие вопросы и дать алгоритм словами,
и только потом код. Файлы прикладывать не нужно, карточка самодостаточная.

## Правила, без которых тренажёр не работает

1. **Сначала вслух.** Одним предложением: что делает функция и как. Не смог сказать — код писать рано.
2. **Не подглядывать в `solution.ts`,** пока не потратил норматив пака.
3. Посмотрел разбор — **сотри свой код и напиши заново сам.** Копирование не считается.
4. Задача сдана, когда написана **с нуля, без разбора, в норматив.** Первый проход не считается,
   считается повтор на следующий день.

## Протокол лайвкода на собесе

1. **Уточни условие.** Размер данных, можно ли мутировать вход, что делать с пустым и невалидным.
2. **Проговори пример.** «На вход `[1,2,3]`, жду `[2,4,6]`. Верно?»
3. **Алгоритм словами.** До кода.
4. **Пиши тупое рабочее решение.** Красоту и оптимизацию — потом и вслух.
5. **Проверь края:** пустой массив, один элемент, отрицательные, дубликаты, `null`.
6. **Назови сложность:** «один проход, O(n) по времени, O(n) по памяти из-за Set».

Убивает собес: молчание, попытка сразу писать идеально, «я не знаю» без продолжения.
Рабочая формулировка: «Точно не помню синтаксис, но идея такая: … Сейчас напишу как помню, потом поправлю.»

### Два пака работают иначе

**`TS` — типы.** Часть задач проверяет компилятор, а не рантайм. Строки
`type _TS13 = Expect<Equal<...>>` — это и есть тесты, удалять их нельзя. Пока тип неверен,
строка красная прямо в редакторе, а `yarn ok` покажет ошибку типов вместо списка проверок.

**`QZ` — что выведет.** Здесь ничего не реализуют, здесь предсказывают. Тесты выполняют тот же код
и сравнивают твой ответ с реальным поведением движка — спорить не с кем.
