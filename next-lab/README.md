# next-lab — база Next.js на практике

Десять работающих примеров по App Router. Next 16, React 19, TypeScript.
Всё проверено сборкой: `yarn build` проходит, маршруты размечены как статические, SSG и динамические.

---

## Запуск

```bash
yarn dev
```

Открыть `http://localhost:3000`. Слева меню с примерами.

---

## Как этим пользоваться

Next на джуновском собесе почти никогда не просят писать вживую — про него **спрашивают**.
Поэтому режим другой, чем в `meme-lab`:

1. Открыл страницу в браузере, потыкал.
2. Открыл её исходник — там подробный комментарий, зачем всё так.
3. Сделал задание из [TASKS.md](./TASKS.md) — сломал и починил своими руками.
4. Ответил вслух на вопросы из [THEORY.md](./THEORY.md).

Понимание проверяется просто: сможешь объяснить, **почему** кнопка не работает без `'use client'` —
значит понял. Не сможешь — перечитай исходник страницы.

## Три вещи, на которых валятся чаще всего

1. **`params` и `searchParams` — это промисы.** С Next 15 их надо `await`.
   Скажешь «это объект» — сразу видно, что учил по статьям 2023 года.
2. **`'use client'` не значит «рендерить только в браузере».** Компонент всё равно
   проходит SSR, а директива лишь помечает модуль как клиентский и кладёт его в бандл.
3. **Route Handler не нужен, чтобы получить данные для своей же страницы.**
   Серверный компонент ходит в базу напрямую — лишний сетевой хоп не нужен.

## Команды

| Команда | Что делает |
|---|---|
| `yarn dev` | режим разработки |
| `yarn build` | продакшн-сборка, показывает таблицу маршрутов |
| `yarn start` | запуск собранного приложения |
| `yarn typecheck` | проверка типов |

Таблица маршрутов после `yarn build` — сама по себе полезная штука:
`○` статика, `●` SSG, `ƒ` динамика по запросу. Понимать, почему страница попала
в ту или иную категорию, — ровно то, что проверяют вопросом про рендеринг.
