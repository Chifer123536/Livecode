# Next.js на собесе — вопросы и ответы

Формат: вопрос, короткий ответ вслух, и что добавить, если попросят подробнее.
Актуально для Next 16 и React 19.

---

## Основы App Router

### Чем App Router отличается от Pages Router?

App Router живёт в папке `app`, Pages Router — в `pages`. Разница не в папке:

- в `app` компоненты по умолчанию **серверные**, в `pages` — всегда клиентские;
- маршрут задаётся файлами-соглашениями: `page`, `layout`, `loading`, `error`, `not-found`, `route`;
- layout не перемонтируется при навигации, в Pages Router `_app` перерисовывался целиком;
- данные получают прямо в компоненте через `async`/`await`, а не через `getServerSideProps`;
- хуки роутера переехали из `next/router` в `next/navigation`.

### Какие файлы-соглашения знаешь?

`layout.tsx` — обёртка сегмента, не перемонтируется.
`page.tsx` — делает сегмент публично доступным.
`loading.tsx` — Suspense-фолбэк сегмента.
`error.tsx` — граница ошибок, обязательно клиентский компонент.
`not-found.tsx` — для `notFound()` и несуществующих адресов.
`route.ts` — HTTP-обработчик вместо страницы.
`template.tsx` — как layout, но перемонтируется на каждой навигации.
`global-error.tsx` — ловит ошибки самого корневого layout.

### В каком порядке они оборачивают друг друга?

`layout` → `template` → `error` → `loading` → `not-found` → `page`.
Отсюда практическое следствие: `error.tsx` сегмента **не поймает** ошибку своего же `layout` —
для неё нужна граница уровнем выше.

## Серверные и клиентские компоненты

### Что такое серверный компонент и зачем он?

Компонент, который выполняется только на сервере. Его код не попадает в бандл,
поэтому он не увеличивает объём JavaScript у пользователя. Может ходить в базу,
читать файлы, использовать секреты. Не может иметь состояние, эффекты и обработчики событий.

### Когда ставить `'use client'`?

Когда нужны `useState`, `useEffect`, обработчики событий, ref на DOM, контекст, браузерные API.
Правило: ставить максимально глубоко, чтобы клиентским стал маленький островок, а не вся страница.

### `'use client'` значит «рендерить только в браузере»?

Нет. Клиентский компонент всё равно рендерится на сервере для первого HTML, а потом гидрируется.
Директива помечает границу: с этого модуля и ниже код попадает в бандл браузера.

### Можно ли импортировать серверный компонент внутрь клиентского?

Нет. Клиентский модуль собирается для браузера, серверный там не выполнить.
Но можно **передать** серверный элемент как проп, обычно через `children` —
клиентская обёртка просто отрисует готовое дерево.

### Что можно передать через границу сервер → клиент?

Только сериализуемое: строки, числа, булевы, массивы, обычные объекты, `Date`, `Map`, `Set`,
промисы, JSX. Нельзя функции (исключение — Server Actions), классы, символы.

## Данные и кэширование

### Как получить данные в App Router?

В серверном компоненте — просто `await` прямо в теле. Никаких `useEffect` и состояния загрузки.
В клиентском — либо получить данные сверху пропсами, либо использовать библиотеку
вроде TanStack Query.

### Почему это лучше, чем загрузка в useEffect?

Нет водопада «сначала отрисовали пустоту, потом запросили, потом отрисовали снова».
HTML приходит уже с данными: лучше и для метрик, и для поисковиков.

### Что изменилось с кэшированием в Next 16?

Появились Cache Components: при включённом флаге `cacheComponents` **ничего не кэшируется
по умолчанию**, кэширование задаётся явно директивой `'use cache'`.
До этого Next кэшировал агрессивно и неявно, за что его много ругали.

### Как сбросить кэш после изменения данных?

`revalidatePath('/posts')` — по маршруту, `revalidateTag('posts')` — по тегу.
В Next 16 добавились `refresh()` (обновить только некэшированные данные) и
`updateTag()` (немедленно показать пользователю его собственную запись).

### Что делает страницу динамической?

Чтение `searchParams`, `cookies()`, `headers()`, а также явный
`export const dynamic = 'force-dynamic'`. Такую страницу нельзя отрендерить заранее —
значения известны только в момент запроса.

## Маршрутизация

### Почему `params` нужно await?

С Next 15 `params` и `searchParams` — промисы. Это сделали, чтобы рендер не блокировался
в ожидании данных запроса и большая часть страницы могла отрендериться заранее.
В клиентском компоненте их читают хуком `use` из React.

### Какие бывают динамические сегменты?

`[id]` — один сегмент. `[...slug]` — catch-all, забирает всё до конца пути массивом.
`[[...slug]]` — необязательный catch-all, подходит и под пустой путь.

### Что такое `generateStaticParams`?

Список значений динамического сегмента, известных на этапе сборки.
Next заранее соберёт эти страницы статически, остальные отрендерит по запросу.

### Чем `<Link>` лучше `<a>`?

Клиентская навигация без полной перезагрузки, префетч при появлении во вьюпорте,
сохранение состояния layout. Обычный `<a>` перезагружает страницу и теряет всё состояние.

### Куда делся `next/router`?

Это Pages Router. В App Router — `next/navigation`:
`useRouter`, `usePathname`, `useSearchParams`, `redirect`, `notFound`.

## Server Actions

### Что это такое?

Асинхронная функция с директивой `'use server'`, которая выполняется на сервере,
а вызывается из клиента. Под капотом — POST-запрос. Передаётся форме через атрибут `action`.

### Где можно объявить Server Action?

Внутри серверного компонента — директивой в теле функции. Либо в отдельном файле
с `'use server'` наверху; тогда все его экспорты становятся Server Actions,
и их можно импортировать в клиентские компоненты. Внутри клиентского компонента объявить нельзя.

### Чем Server Action лучше обычного fetch на роут?

Не нужно писать эндпоинт, сериализовать тело, обрабатывать ответ и вручную обновлять UI.
Плюс работает прогрессивное улучшение: форма отправится, даже если JavaScript не загрузился.

### Где здесь дыра в безопасности?

Server Action — это публичный POST-эндпоинт. Его можно дёрнуть напрямую, минуя вашу форму.
Проверка авторизации и прав обязана быть **внутри** функции, а не только в интерфейсе.

### Что такое `useActionState`?

Клиентский хук: `const [state, formAction, pending] = useActionState(action, initialState)`.
Экшен получает предыдущее состояние первым аргументом и `FormData` вторым,
а возвращённое значение становится новым состоянием. Заменил `useFormState`
и заодно отдаёт флаг `pending`.

### Чем `useFormStatus` отличается от `pending` из `useActionState`?

`useFormStatus` читает состояние **ближайшей родительской формы** и работает только
в компоненте, который лежит внутри `<form>`. В самой форме он вернёт `false`.
Поэтому кнопку отправки выносят в отдельный компонент.

## Route Handlers

### Когда нужен `route.ts`, а когда нет?

Нужен для вебхуков, публичного API, OAuth-колбэков, отдачи файлов — всего, что дёргают снаружи.
Не нужен, чтобы получить данные для своей же страницы: серверный компонент сходит в базу
напрямую. Не нужен для форм: для них есть Server Actions.

### Чем отличается от API Routes в Pages Router?

Работает со стандартными Web API `Request` и `Response`, а не с `req`/`res` из Express.
Методы экспортируются по именам: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`.
В одном сегменте не может быть одновременно `page.tsx` и `route.ts`.

## Рендеринг: термины, которые надо различать

| Термин | Когда рендерится | Как получить |
|---|---|---|
| Static (SSG) | на этапе сборки | по умолчанию, плюс `generateStaticParams` |
| ISR | на сборке, потом обновляется по времени | `revalidate` |
| Dynamic (SSR) | на каждый запрос | чтение `cookies`, `headers`, `searchParams` |
| CSR | в браузере | `'use client'` плюс загрузка данных на клиенте |

После `yarn build` Next печатает таблицу маршрутов с пометками `○`, `●`, `ƒ`.
Уметь объяснить, почему конкретная страница попала в свою категорию, — и есть проверка понимания.

## Частые ошибки новичков (спрашивают как «а что тут не так»)

1. `'use client'` на самой верхней странице — весь код уезжает в бандл.
2. `useEffect` + `fetch` в серверном приложении вместо `await` в компоненте.
3. Забытый `await` у `params` — получишь промис вместо объекта.
4. Создание `route.ts` ради данных для собственной страницы.
5. Проверка прав только в интерфейсе, без проверки внутри Server Action.
6. `useSearchParams` без обёртки `<Suspense>` — падает сборка.
7. `next/router` вместо `next/navigation`.
8. Секреты в переменной с префиксом `NEXT_PUBLIC_` — она попадает в бандл браузера.
